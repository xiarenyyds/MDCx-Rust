# 功能与使用

首次启动及系统要求见[安装与使用](INSTALLATION.md)，NAS 和服务器部署见 [Docker 部署](DOCKER.md)。本页介绍刮削规则、配置方案及日常操作。

## 完成一次刮削

1. 选择待处理媒体目录，确认影片类型、输出目录，以及移动、重命名和清理设置。
2. 选择对应类型的网站及排序，设置需要的 NFO 字段、图片、字幕和命名模板。
3. 按需填写代理、Cookie、站点账号或接口令牌，然后保存配置。
4. 开始刮削，在运行状态查看成功、失败和跳过记录，通过日志管理查看来源及失败原因。

首次使用可先处理少量影片，确认最终目录、文件名和封面符合预期，再扩大范围。点击停止后不再派发新影片，已经开始的影片会处理完成。

## 选择刮削方式

支持 33 个影片来源，可为有码、无码、欧美、FC2、国产等类型分别设置网站及顺序。

| 方式 | 获取规则 | 适用情况 |
| --- | --- | --- |
| 速度优先 | 按当前影片类型的网站顺序查询，取首个成功结果，不继续为缺失字段补查后续网站 | 优先减少请求，接受单站资料 |
| 字段优先 | 从启用网站中汇总各字段需要的来源，并发获取后按各字段排序取值 | 标题、演员、简介、封面等需要分别选用来源 |
| 单站 | 使用指定网站获取资料 | 已知来源或排查单个网站 |

字段优先由配置顺序决定最终结果，请求先完成的网站不会因此获得更高优先级。未启用网站的资料不参与选用。

指定详情页手动刮削可直接更新对应网站资料，适合纠正匹配结果或主动刷新。网站需要认证时，先在网络设置中配置相应账号、Cookie 或接口令牌。

## 全局设置与刮削方案

| 设置范围 | 内容 | 保存位置 |
| --- | --- | --- |
| 全局共用 | 代理、站点认证与接口地址、翻译服务账号、通知、演员管理、常用工具、媒体助手、高级设置和界面偏好 | `data/config/global.json` |
| 按方案保存 | 刮削目录、网站与字段优先级、命名、翻译策略、字幕、NFO 和封面洗版设置 | 默认方案 `data/config/config.json`，其他方案 `data/config/方案名.json` |

切换方案会更新软件当前选择，后续刮削、洗版及定时任务使用该方案；运行中的任务继续使用启动时的设置。通知、代理和媒体服务器连接等全局设置始终共用。

当前配置旁的“导入”“导出”用于分享刮削方案。导出读取已经保存的内容，不包含全局账号、代理和通知；有修改未保存时，两项操作均不可用。导入后检查媒体路径是否适用于当前电脑或容器，覆盖同名方案前会确认。

“恢复默认”仅重置当前刮削方案，全局设置保持不变。保存校验失败时，按弹窗中的原因和设置位置修正后重试。

## 离线资料与重复刮削

“数据同时写入本地数据库”和“优先读取本地数据库”默认开启，分别控制影片资料的写入与读取。

| 优先读取 | 同时写入 | 实际行为 |
| --- | --- | --- |
| 开启 | 开启 | 优先复用可用本地资料，需要联网时保存新获取的资料 |
| 开启 | 关闭 | 可读取已有资料，新获取的资料不自动写入 |
| 关闭 | 开启 | 联网获取并保存资料 |
| 关闭 | 关闭 | 不读取或写入影片离线资料库 |

网站资料分别保存，重新刮削时按当前网站与字段顺序选用。有可用缓存时，不会仅因某个字段为空而反复请求，也不会自动补查未缓存的后备网站；没有可用资料时才联网获取。需要更新网站资料时，可使用手动强制联网或指定详情页刮削。

本地缓存保存的是影片资料及资源网址。图片下载、尚未缓存的翻译等操作仍可能联网；关闭剧照、预告片等下载，只影响对应下载和资源日志，取得的原始资料仍可按写入设置保存。

离线资料与刮削成功记录相互独立。清空运行记录不会删除离线资料，修改资料库也不会自动改写媒体目录中已有的 NFO 和图片。

首次启动的资料库为空。在数据管理中可按需下载 [Amazon ASIN、演员资料、演员及信息映射库](https://github.com/xiarenyyds/databases)；下载成功会完整替换对应本地库，包括本地维护结果，失败保留原库。影片离线资料由实际刮削积累。

## 命名、NFO 与封面

命名支持 Jinja2 变量、条件和过滤器，可组合番号、标题、演员、字幕和清晰度等信息。目录与文件名模板支持子目录，命名页可查看变量说明及示例预览。

按需要选择 NFO 字段和下载资源，封面、背景图、缩略图、剧照与预告片分别控制。NFO 编辑及批量修改适合维护已有媒体资料；封面洗版适合批量重做图片。

自动刮削、封面洗版与手动图片处理共用当前方案的封面规则。可配置高清封面搜索、网站图片选优、各影片类型的人脸裁剪及水印；网站现成竖图和 Amazon 海报保留完整构图。启用人脸裁剪后未检测到人脸或检测失败时，保留完整原图。

翻译服务的账号和接口全局共用，影片字段的翻译策略按方案保存。软链接、硬链接与 STRM 可按需要配置额外输出，并选择是否同时存放 NFO、封面等资料。

## 演员管理

填写 Emby／Jellyfin 的服务器地址和 API 密钥，选择需要处理的媒体库后加载演员。列表按所选媒体库分页获取，作品详情在点击演员后加载。

演员资料按启用网站及其顺序逐字段选用。“演员资料库”默认排在来源首位；启用时，已有演员记录直接复用本地资料，字段缺失不自动触发联网。仅整条记录不存在时，才并发请求所选网站并分别保存；删除该记录后可重新获取。

列表中的获取操作针对勾选演员；补全设置中的批量操作处理所选媒体库的符合条件演员。获取资料后可预览、修改，并按需要同步资料或图片。相关任务记录在“日志管理 → 演员管理”查看。

## Telegram 与 Bark 通知

在“通知”页选择平台，填写连接信息并启用，可分别发送单片成功、单片失败及任务结束汇总。配置全局共用，两个平台共用标题和正文模板。

| 平台 | 必填信息 | 图片方式 |
| --- | --- | --- |
| Telegram | 机器人 Token、数字 Chat ID；API 地址通常使用默认值 | 上传本地图片或使用网络图片 |
| Bark | 服务器地址、设备密钥；分组按需填写 | 使用网络图片，选中本地图片时回退到可用网络图 |

在正文中将图片变量单独写一行即可附图，例如 `{{ local_fanart or local_thumb or local_poster or image_url }}`。按顺序选第一项可用图片，一条通知只选一张。Telegram 显示顶部大图；Bark 的展开样式由系统决定，图片网址需能被接收端访问。

可从默认模板开始修改，通知页右上角可查看全部变量。标题示例为 `MDCx · {{ event }} · {{ status }}`，正文可使用：

```jinja2
{% if number or path %}{{ local_fanart or local_thumb or local_poster or image_url }}
🎬 {{ number or '未识别番号' }}
📌 {{ title or '暂无标题' }}
👥 {{ all_actor or '未知' }}
{% if outline %}
📝 {{ outline }}
{% endif %}
📁 {{ path }}
{% else %}📊 刮削任务汇总
{% endif %}
状态：{{ status }}
总数：{{ total }}
成功：{{ success }} · 失败：{{ failed }} · 跳过：{{ skipped }}
耗时：{{ duration }} 秒
{% if error %}❌ {{ error }}{% endif %}
```

`{% if number or path %}` 区分单片通知和任务汇总；未识别出番号但有路径的失败影片也会进入单片分支。消息超长时优先缩短简介，再按平台容量处理其他内容。测试通知使用示例资料，不包含图片；修改后保存，使后续任务使用新设置。

### Telegram 机器人

启用“启用tg机器人”后，私聊使用正数 Chat ID 授权本人；群聊填写负数群 ID，并指定允许操作的用户 ID，多个用户用逗号分隔。

| 指令 | 操作 |
| --- | --- |
| `/start`、`/menu` | 打开控制菜单 |
| `/profiles` | 查看并切换软件当前方案 |
| `/scrape` | 按当前方案扫描目录并开始刮削 |
| `/progress` | 查询进度、数量及正在处理的影片 |
| `/status` | 查看方案、后台任务及定时刮削状态 |

软件或服务端需保持运行，无需额外开放机器人入站端口。同一个机器人只由一个实例使用，不与 Webhook 同时启用；有刮削或洗版任务运行时不会重复启动。

## Emby 媒体助手

主菜单“媒体助手”中点击“下载插件”，或从 [MediaAssistant](https://github.com/xiarenyyds/MediaAssistant) 下载 DLL 并按插件文档安装。配置 MDCx 监听地址、端口、服务令牌及路径映射，保存后开始监听。

媒体助手与 Web 登录使用各自的令牌。Emby 与 MDCx 路径相同且能访问同一文件时无需映射；路径不同则映射到 MDCx 实际可访问的目录，Docker 中填写容器内路径。任务记录在“日志管理 → 媒体助手”查看。

## 日志与排查

“日志管理”按系统、刮削、媒体助手、常用工具、封面洗版、演员管理及 NFO 批量修改分类查看。日志按 20 MB 分卷并保留 7 天，可开启详细日志查看技术细节。

## 常见问题

| 情况 | 检查方式 |
| --- | --- |
| 切换方案后路径不可用 | 桌面填写本机路径，Docker／Web 填写后台实际可访问的路径；修正并保存，通过检查后恢复任务 |
| 读取离线资料仍有联网请求 | 区分影片元数据、图片下载、翻译及演员补全，查看日志确认实际请求用途 |
| 网站始终没有某个字段 | 已缓存资料不会为该空字段反复联网；需要其他资料时调整来源，并主动刷新 |
| 修改数据库后已有影片未变化 | 资料库维护影响后续处理，已有 NFO 或封面需重新执行相应操作 |
| Telegram 菜单没有出现 | 保存机器人设置后发送 `/start` 或 `/menu`，核对 Chat ID、群聊授权及网络连接 |
| 保存设置失败 | 按校验弹窗定位错误字段；路径还需检查后台可访问性与目录权限 |
